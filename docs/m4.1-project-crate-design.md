# M4.1 — `crates/project` design

**Status:** architect pass, pre-implementation. The crate is named
`i18n-harness-project` on the workspace (snake-cased to match the rest of
the workspace at [`Cargo.toml:3`](../Cargo.toml)).

This document is the contract. It pins the public surface, the
round-trip preservation policy for the manifest, the discovery
heuristic, the locale-layering rule, the error model, the translation
memory store, the state-path resolution policy, and the workspace
dependency edges. Eight downstream M4.x milestones (M4.2 through M4.10,
per [`roadmap-product.md`](roadmap-product.md)) sit on top of this
surface — getting it wrong cascades, which is why this document exists
before any code lands.

The design honors two non-negotiable invariants from `CLAUDE.md`:

1. Languages, engines, and formats are **data or plugins behind stable
   extension points**. The project crate stores per-locale config as
   data and dispatches catalog I/O through the existing format
   discriminator — it never names a specific engine in its logic.
2. The model translates text; **deterministic Rust does everything
   else**. The project crate is fully deterministic: it owns I/O,
   resolution, validation, and persistence — but no calls into a
   backend live here.

---

## 0. Scope statement

The project crate **does** own:

- The manifest type (`ProjectManifest`) and a `Project` value that
  bundles the manifest + resolved paths + catalog index + glossary.
- Reading, validating, mutating, and saving `i18n-harness.toml` with
  user comments/ordering preserved.
- The discovery heuristic that runs when there is no manifest yet.
- The merge of workspace-locale records with per-project locale
  overrides into a single view a backend or gate can consume.
- The translation-memory store (`corrections.jsonl` + `curated.toml`).
- The resolution of every project-relative path
  (`<project>/.i18n-harness/metrics.jsonl`, `tuning/<ts>/...`, etc.) so
  that the gate, backend, and UI receive absolute paths from a single
  source.
- A `ProjectFs` trait abstracting filesystem access so unit tests
  exercise the whole crate against an in-memory backing.

The project crate **does not** own:

- Catalog parsing/serialization (lives in `adapter-qt`, `catalog`).
- Backend execution (lives in `backend`).
- Gate validation (lives in `gate`).
- Tauri command dispatch (lives in `ui/src-tauri`, M4.2).
- Multi-project workspaces, project templates, cloud sync, or
  cross-project anything (explicitly deferred — see §10).

### 1.2 `ProjectManifest` (read view)

Pure-serde shape of the on-disk manifest. Used for *reading and
validating*. Mutation goes through `Project::*` methods backed by
`toml_edit::DocumentMut` — see §2.

```rust
pub const SCHEMA_VERSION: u32 = 1;

/// Pure-serde read view of `i18n-harness.toml`. Construct via
/// `ProjectManifest::from_toml` or `Project::open`; never edit this in
/// place to mutate the file — go through `Project::set_*` /
/// `Project::add_*`, which preserve comments and ordering.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct ProjectManifest {
    pub project: ProjectMeta,
    #[serde(default)]
    pub locales: BTreeMap<String, LocaleConfig>,
    #[serde(default)]
    pub catalogs: Vec<CatalogEntry>,
    pub glossary: Option<GlossaryConfig>,
    #[serde(default, rename = "backend")]
    pub backends: BackendBlock,
    pub prompts: Option<PromptsConfig>,
    #[serde(default)]
    pub paths: PathsConfig,
}

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct ProjectMeta {
    pub name: String,
    pub schema: u32,
}

#[derive(Debug, Clone, Default, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct LocaleConfig {
    #[serde(skip_serializing_if = "Option::is_none")]
    pub register: Option<RegisterOverride>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub variant: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub length_warn_ratio: Option<f32>,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum RegisterOverride { Formal, Informal, Neutral }

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct CatalogEntry {
    pub path: PathBuf,
    pub format: CatalogFormat,
    pub locale: String,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum CatalogFormat { QtTs, GettextPo, IcuJson }

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct GlossaryConfig {
    pub path: PathBuf,
}

#[derive(Debug, Clone, Default, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct BackendBlock {
    pub default: Option<BackendConfig>,
}

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct BackendConfig {
    pub kind: BackendKind,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub model: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub host: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub num_ctx: Option<u32>,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum BackendKind { Manual, Ollama, OpenAiCompatible, Agent }

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(deny_unknown_fields)]
pub struct PromptsConfig {
    pub template_dir: PathBuf,
}

/// Override for any of the state paths the project resolves. All fields
/// optional; absent fields fall through to the in-tree defaults
/// (`<project>/.i18n-harness/<name>`). See §7.
#[derive(Debug, Clone, Default, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct PathsConfig {
    pub state_dir: Option<PathBuf>,
}
```

Constructors / readers:

| Method | Purpose |
|---|---|
| `ProjectManifest::from_toml(&str) -> Result<(Self, Vec<ProjectWarning>), ProjectError>` | Parse + validate text. Same shape as `Glossary::from_toml` for symmetry. |
| `ProjectManifest::load(path: &Path, fs: &dyn ProjectFs) -> Result<(Self, Vec<ProjectWarning>), ProjectError>` | Read from `fs` and parse. |
| `ProjectManifest::schema_version(&self) -> u32` | Convenience. |
| `ProjectManifest::default_backend(&self) -> Option<&BackendConfig>` | Convenience accessor. |

`ProjectManifest` is **read-only after construction**. All edits go
through `Project`, which keeps a parallel `toml_edit::DocumentMut` and
rebuilds the manifest from it after each edit.

### 1.3 `Project` (the live in-memory value)

```rust
/// A loaded, validated project. Owns the manifest, the resolved paths,
/// the catalog index, the parsed glossary, the comment-preserving TOML
/// document for save-back, and a `dyn ProjectFs` for I/O.
///
/// # Invariants
/// - `manifest.project.schema == SCHEMA_VERSION` (loader rejects future
///   versions, accepts older through forward-compatible migrations).
/// - Every `CatalogEntry.path` exists on disk and matches its declared
///   `format` (see `Project::open` validation policy).
/// - Every `CatalogEntry.locale` either resolves through
///   `Locale::by_id` or is logged as a `ProjectWarning::UnknownLocale`
///   (we do not hard-fail on unknown locale ids — see §4).
/// - `glossary` is `Some` iff the manifest has a `[glossary]` table
///   AND the file loaded.
/// - `paths.state_dir()` is absolute and exists (created on `open` if
///   absent, since the dir is gitignored anyway).
///
/// # What `Project` does NOT guarantee
/// - That catalogs parse cleanly. `Project::open` validates *existence
///   and format-classification* on every catalog but does **not**
///   pre-parse them — pre-parsing every PO and `.ts` on every open
///   would dominate startup. `Project::open_catalog(path)` returns the
///   format-specific parse on demand.
/// - That the glossary's `[locale.*]` overrides are consistent with
///   the manifest's `[locales.*]` blocks. The two override layers stack
///   (glossary wins; see §4) and both are kept verbatim.
pub struct Project {
    /* private */
}

impl Project {
    // ── Read path ──────────────────────────────────────────────────

    /// Load and validate a project rooted at `root`. Reads
    /// `<root>/i18n-harness.toml`, parses, resolves every declared
    /// catalog, loads the glossary if present, and creates the state
    /// directory if it does not exist.
    ///
    /// # Errors
    /// - `ProjectError::ManifestMissing` if no `i18n-harness.toml` at
    ///   `root` (caller can fall back to `Project::discover`).
    /// - `ProjectError::ManifestParse` if the TOML is malformed.
    /// - `ProjectError::UnsupportedSchemaVersion` if the manifest's
    ///   schema is newer than this binary supports.
    /// - `ProjectError::CatalogNotFound { path }` if a `[[catalogs]]`
    ///   entry points at a non-existent file.
    /// - `ProjectError::CatalogFormatMismatch { path, declared, sniffed }`
    ///   if a file does not match its declared format (e.g. a file
    ///   declared `qt-ts` whose first non-comment bytes are `{`).
    /// - `ProjectError::Glossary` (transparent) if the glossary file is
    ///   declared but fails to load.
    /// - `ProjectError::Io { path, source }` for filesystem failures.
    pub fn open(root: &Path) -> Result<(Self, Vec<ProjectWarning>), ProjectError>;
    pub fn open_with_fs(root: &Path, fs: Arc<dyn ProjectFs>) -> Result<(Self, Vec<ProjectWarning>), ProjectError>;

    /// Discover a project from a directory with no manifest. Returns a
    /// `DraftManifest` the caller (UI or CLI) presents for confirmation
    /// before calling `Project::create_from_draft` to persist.
    pub fn discover(root: &Path) -> Result<DraftManifest, ProjectError>;
    pub fn discover_with_fs(root: &Path, fs: Arc<dyn ProjectFs>) -> Result<DraftManifest, ProjectError>;

    /// Create a new manifest at `root/i18n-harness.toml` from a
    /// draft and load the resulting project. Used by `harness init`
    /// and the UI's "Create from this folder" path.
    pub fn create_from_draft(root: &Path, draft: DraftManifest) -> Result<(Self, Vec<ProjectWarning>), ProjectError>;

    /// Borrow the validated manifest (read view).
    pub fn manifest(&self) -> &ProjectManifest;

    /// Borrow the catalog index (no I/O; pre-resolved on `open`).
    pub fn catalogs(&self) -> &[CatalogRef];

    /// Look up a catalog by its manifest-relative or absolute path.
    /// Returns `None` if the path does not match a registered catalog
    /// — the project does not allow ad-hoc opening of catalogs not in
    /// the manifest (those are handled via the M4.2 "ephemeral single-
    /// catalog project" shim).
    pub fn catalog(&self, path: &Path) -> Option<&CatalogRef>;

    /// All resolved paths under the project (state dir, metrics file,
    /// corrections file, etc.). See [`ProjectPaths`].
    pub fn paths(&self) -> &ProjectPaths;

    /// Borrow the loaded glossary, if any.
    pub fn glossary(&self) -> Option<&Glossary>;

    /// Resolve a locale id through the workspace `Locale::by_id` table
    /// + the manifest's per-locale overrides + the glossary's per-
    /// locale overrides. Returns `None` if the workspace does not know
    /// the locale (the manifest may have logged a warning).
    pub fn locale(&self, id: &str) -> Option<ResolvedLocale>;

    /// Iterate every locale id declared in the manifest (in TOML
    /// document order; preserved across saves).
    pub fn locale_ids(&self) -> impl Iterator<Item = &str>;

    /// Compact summary safe to send over the Tauri IPC bridge. See
    /// [`ProjectSummary`] for the field shape.
    pub fn summary(&self) -> ProjectSummary;

    // ── Mutation path (TOML round-trip preserving) ─────────────────

    /// Add a new catalog. Appends to `[[catalogs]]` in document order
    /// at the end of the existing array; preserves all comments and
    /// blank lines around the existing entries.
    ///
    /// # Errors
    /// - `ProjectError::DuplicateCatalogPath` if `path` already appears
    ///   in the manifest.
    /// - `ProjectError::CatalogFormatMismatch` if the file disagrees
    ///   with `entry.format`.
    pub fn add_catalog(&mut self, entry: CatalogEntry) -> Result<(), ProjectError>;

    /// Remove the catalog whose path matches. Idempotent — returns
    /// `Ok(false)` if no entry matched, `Ok(true)` if one was removed.
    pub fn remove_catalog(&mut self, path: &Path) -> Result<bool, ProjectError>;

    /// Upsert a locale config block. If the locale id is new, the
    /// block is appended after the last existing `[locales.*]` block;
    /// otherwise the existing block's fields are replaced (preserving
    /// any unknown sibling keys for forward compat — see §2).
    pub fn update_locale(&mut self, id: &str, config: LocaleConfig) -> Result<(), ProjectError>;

    /// Remove a locale config block. Idempotent.
    pub fn remove_locale(&mut self, id: &str) -> Result<bool, ProjectError>;

    /// Replace the `[backend.default]` block.
    pub fn set_backend(&mut self, config: BackendConfig) -> Result<(), ProjectError>;

    /// Replace the `[glossary]` table.
    pub fn set_glossary(&mut self, config: GlossaryConfig) -> Result<(), ProjectError>;

    /// Replace the `[prompts]` table.
    pub fn set_prompts(&mut self, config: PromptsConfig) -> Result<(), ProjectError>;

    /// Write the manifest back to `<root>/i18n-harness.toml` atomically
    /// (write to temp, fsync, rename). Comments, key order, and blank
    /// lines from the original file survive every prior mutation.
    pub fn save_manifest(&self) -> Result<(), ProjectError>;

    // ── Translation memory ─────────────────────────────────────────

    /// Open the project's correction store. Cheap — opens lazily on
    /// first append; safe to call from a hot path.
    pub fn corrections(&self) -> &CorrectionStore;

    /// Append a `Correction` to `corrections.jsonl`. Returns the
    /// generated `CorrectionId` so the caller can promote it to
    /// curated later. See §6 for the keying rule.
    pub fn record_correction(&self, c: NewCorrection) -> Result<CorrectionId, ProjectError>;

    /// List corrections matching `filter` (locale, catalog path,
    /// unit_id, since-ts). Reads the whole file (it is append-only
    /// JSONL; project sizes are bounded by translator throughput).
    pub fn list_corrections(&self, filter: CorrectionFilter) -> Result<Vec<Correction>, ProjectError>;

    /// Promote a correction to the curated set. Updates `curated.toml`
    /// (round-trip-preserved like the manifest); does not modify
    /// `corrections.jsonl`.
    pub fn promote_to_curated(&mut self, id: CorrectionId, note: Option<String>) -> Result<(), ProjectError>;

    /// Read the curated set.
    pub fn curated(&self) -> &CuratedSet;
}
```

### 1.4 Wire-shaped value types

These exist for Tauri's IPC bridge — they are intentionally smaller and
cheaper to serialize than `Project` itself.

```rust
/// Cloneable summary the UI binds against. Excludes the catalog parses
/// (those come from `open_catalog_in_project`) and the glossary
/// payload (separate Tauri command). String, not PathBuf, in fields
/// the JS layer reads (TS does not have a PathBuf).
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub struct ProjectSummary {
    pub root: String,
    pub name: String,
    pub schema: u32,
    pub locales: Vec<String>,
    pub catalogs: Vec<CatalogRef>,
    pub glossary_path: Option<String>,
    pub backend: Option<BackendConfig>,
    pub state_dir: String,
}

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub struct CatalogRef {
    /// Absolute path on disk.
    pub absolute_path: String,
    /// Path relative to the project root (the form the manifest stores).
    pub manifest_path: String,
    pub format: CatalogFormat,
    pub locale: String,
    pub status: CatalogStatus,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize)]
#[serde(rename_all = "kebab-case")]
pub enum CatalogStatus {
    /// File present, format classification matches declared format.
    Ok,
    /// File missing on disk. Manifest references it but `Project::open`
    /// could not find it. The UI shows this as a broken row instead of
    /// failing the whole open — that way the user can fix or remove
    /// the entry without first hand-editing the manifest.
    Missing,
    /// File present but content sniffer disagrees with declared format.
    /// UI offers "re-declare" or "remove".
    FormatMismatch,
}
```

`Project::open` is *strict* on existence (fails on `CatalogNotFound`)
but the UI's `discover_project` path returns `CatalogStatus::Missing`
for soft handling. The rule: **opening a manifest the user wrote is
strict; building a draft from inference is permissive.** This way the
user gets a clear error when their committed file is broken, but
exploring an unfamiliar tree never throws.

### 1.5 Draft manifest (discovery output)

```rust
/// What `Project::discover` produces — a manifest the user reviews
/// before it is written to disk.
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct DraftManifest {
    pub root: PathBuf,
    /// Best-guess project name (from the directory's leaf).
    pub name: String,
    pub locales: BTreeMap<String, LocaleConfig>,
    pub catalogs: Vec<DraftCatalog>,
    pub glossary: Option<GlossaryConfig>,
    pub backend: Option<BackendConfig>,
}

#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct DraftCatalog {
    pub path: PathBuf,
    /// Best guess; UI shows alternatives with `alternatives` when
    /// confidence is below `High`.
    pub format: FormatGuess,
    pub locale: Option<String>,
    pub confidence: ClassificationConfidence,
    /// Reason the guess fired, e.g. "TS root element seen at byte 12"
    /// or "filename matches /(?:_\|-)([a-z]{2}(?:_[A-Z]{2})?)\.json$/".
    /// Free-form; surfaced verbatim in the UI for transparency.
    pub reason: String,
    /// Other plausible (format, locale) interpretations the heuristic
    /// found. Empty when `confidence == High`.
    pub alternatives: Vec<DraftAlternative>,
}

#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct DraftAlternative {
    pub format: FormatGuess,
    pub locale: Option<String>,
    pub reason: String,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum FormatGuess {
    QtTs,
    GettextPo,
    IcuJson,
    /// File looked plausible but neither sniff nor extension confirmed
    /// a format. UI shows it greyed out with "skip" preselected.
    Unknown,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "kebab-case")]
pub enum ClassificationConfidence {
    /// Extension + content sniff agree, locale found via primary rule.
    High,
    /// Extension matched but content sniff is ambiguous, OR locale
    /// inferred via filename-only fallback.
    Medium,
    /// Best-effort guess; user should confirm.
    Low,
}
```

### 1.6 Resolved locale view

```rust
/// The merged view of one locale: workspace-immutable fields from
/// `crates/locales`, project-overridable fields from the manifest, and
/// glossary-overridable fields. See §4 for the layering rule.
#[derive(Debug, Clone, Copy)]
pub struct ResolvedLocale {
    /* private fields */
}

impl ResolvedLocale {
    /// Locale id (e.g. `"de_DE"`).
    pub fn id(&self) -> &str;
    /// CLDR plural categories. **Workspace-immutable.**
    pub fn cldr_plural(&self) -> &'static [PluralCategory];
    /// Plural arity. **Workspace-immutable.**
    pub fn plural_arity(&self) -> u32;
    /// Script. **Workspace-immutable.**
    pub fn script(&self) -> Script;
    /// Effective register (manifest > glossary > workspace default).
    pub fn register(&self) -> Register;
    /// Effective variant tag (manifest > glossary > workspace default).
    pub fn variant(&self) -> &str;
    /// Effective length-warn ratio (manifest > workspace default).
    /// Glossary cannot override this — it has no `length_warn_ratio`
    /// field, by design.
    pub fn length_warn_ratio(&self) -> f32;
    /// Borrow the underlying workspace `Locale` for callers that
    /// already accept `&Locale` (gate today takes `&Locale`).
    ///
    /// **Caveat:** the returned `&Locale` carries the *workspace*
    /// register / variant / length_warn_ratio. Callers that need the
    /// effective values must read them through `self.register()` etc.
    /// rather than through the returned reference. We do not synthesize
    /// a fresh `&'static Locale` because `Locale` fields are
    /// `&'static str` and that would require leaking memory.
    pub fn workspace_locale(&self) -> &'static Locale;
}
```

The gate currently takes `&Locale` directly. **We do not change the
gate signature in M4.1.** Callers (CLI, Tauri command layer) pass
`resolved.workspace_locale()` to the gate today; the override layering
for `register`/`variant` only matters to the backend at prompt time.
A follow-up M4.x can introduce a gate signature change if/when the
gate starts using length_warn_ratio from the project. Until then this
split keeps the gate untouched and the project crate non-invasive.

### 1.8 Translation memory types

```rust
/// Append-only correction store backed by
/// `<state_dir>/corrections.jsonl`. One line per accepted human edit.
/// See §6 for the keying and storage rule.
pub struct CorrectionStore {
    /* private */
}

/// Stable, content-addressed id for a correction. Format:
/// `"corr_<12-hex>"` where the hex is the first 12 chars of a SHA-256
/// over `(catalog_manifest_path, unit_id, source, mt_proposal,
/// human_target, ts_micros)`. Stored as a string so it round-trips
/// through TOML/JSON without precision loss.
#[derive(Debug, Clone, PartialEq, Eq, Hash, serde::Serialize, serde::Deserialize)]
pub struct CorrectionId(pub String);

/// On-the-wire correction record. One line per record in JSONL.
///
/// The `provenance` block records the exact prompt + model + glossary
/// version a correction was produced against. **This matters because
/// the M4.10 tuning loop compares prompt versions: without this, you
/// cannot tell whether prompt v7 + glossary v3 was better or worse
/// than prompt v8 + glossary v3.** See
/// `docs/feedback-2026-05-24-chatgpt.md` §9 for the rationale; we
/// extended the schema before M4.1d ships rather than after, because
/// historical corrections cannot be backfilled with provenance later.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct Correction {
    /// Schema version (separate from the manifest's). Bumped on each
    /// breaking change to the line shape.
    pub schema: u32,
    pub id: CorrectionId,
    /// RFC3339 microsecond UTC ts.
    pub ts: String,
    /// Manifest-relative path (so corrections survive a project move).
    pub catalog: PathBuf,
    pub locale: String,
    pub unit_id: UnitId,
    pub source: String,
    /// What the model proposed (or empty string if human translated
    /// from scratch — Skipped / manual entry).
    pub mt_proposal: String,
```

## 2. Manifest TOML round-trip preservation

**The rule:** every mutation to `i18n-harness.toml` preserves user
comments, key ordering inside tables, blank-line spacing between
tables, inline-comment positions, and indentation. The reverse-pass
read view (`ProjectManifest`) is **purely a query layer**; it never
participates in serialization back to disk.

### 2.1 The hybrid

```
on-disk i18n-harness.toml
  │
  │  read    ┌──────────────────────┐
  ├────────► │ toml_edit::DocumentMut│   ← source of truth for writes
  │          └─────────┬────────────┘
  │                    │ to_string() on save
  │                    ▼
  │           atomic write back
  │
  │  read    ┌──────────────────────┐
  └────────► │  serde-derived       │   ← source of truth for reads
             │  ProjectManifest     │
             └──────────────────────┘
```

`Project` holds **both**: a `toml_edit::DocumentMut` (private,
field-name `doc`) and a `ProjectManifest` (private, field-name
`manifest`, exposed via `manifest()`).

- On `Project::open` we parse the file once into `DocumentMut` and
  once into `ProjectManifest` (via
  `toml::from_str(&doc.to_string())` — i.e. the manifest is derived
  from the doc, never read independently).
- Every mutation method (`add_catalog`, `update_locale`, etc.)
  manipulates `doc` using `toml_edit`'s table/array operations, then
  rebuilds the in-memory `manifest` from the new `doc.to_string()`.
  This keeps the two views *exactly* consistent — we cannot drift,
  because the manifest is always a function of the doc.
- `save_manifest` is `fs.write_atomic(path, doc.to_string().as_bytes())`.

### 2.2 Why a hybrid (and why not just `toml_edit`)

A pure-`toml_edit` API would force every reader to navigate
`doc["catalogs"][i]["format"].as_str()` with `Option` handling at every
node — verbose at every callsite, no type-safe enum for
`CatalogFormat`, and no `deny_unknown_fields` validation. A
pure-serde API loses comments. The hybrid pays for itself: callers
get an ergonomic typed manifest for reading and a comment-preserving
mutator for writing, with the manifest deterministically derivable
from the doc on every step.

### 2.3 The mutation surface (concrete behavior)

| Operation | `toml_edit` behavior |
|---|---|
| `add_catalog(entry)` | Append a new `[[catalogs]]` table to the array; preserve the blank line and trailing comment of the previous-last entry by inserting after it. New entry uses canonical key order: `path`, `format`, `locale`. |
| `remove_catalog(path)` | Remove the matching `[[catalogs]]` entry; preserve surrounding blank lines (do not collapse to nothing). |
| `update_locale(id, config)` | If `[locales.<id>]` exists, set each field present in `config` and leave absent fields untouched (so a user-added experimental key in that table survives — see §2.4). If it does not exist, append a new `[locales.<id>]` table after the last existing `[locales.*]` block. |
| `remove_locale(id)` | Remove the matching `[locales.<id>]` table. |
| `set_backend(config)` | Replace every field of `[backend.default]`, creating the table if absent; preserve any unknown sibling keys. |
| `set_glossary(config)` | Same shape as `set_backend`. |
| `set_prompts(config)` | Same shape. |

### 2.4 `deny_unknown_fields` vs forward compat — the tension

The manifest types use `#[serde(deny_unknown_fields)]` so that a typo
like `regsiter = "formal"` is a hard error, not a silently-ignored
field. **But** a strict deny on the *read* path would also reject
forward-compat keys (a future v2 manifest field opened by a v1
binary).

Resolution: the *root* manifest does not use
`deny_unknown_fields`. Sub-tables (`LocaleConfig`, `CatalogEntry`,
`BackendConfig`, `GlossaryConfig`, `PromptsConfig`) do, because typos
in those are the common failure mode and v2-only fields will live in
new tables, not new sub-keys of existing ones.

When `update_locale` mutates a `[locales.<id>]` block, `toml_edit`
naturally preserves unknown sibling keys (we set only known fields).
The serde view re-parses and rejects unknown fields, so a future v2
unknown field added inside `[locales.<id>]` would trip
`ProjectError::ManifestParse` on every `save_manifest` round-trip.
We accept this for v1 — when v2 lands, we either bump
`SCHEMA_VERSION` (forcing migration) or remove
`deny_unknown_fields` on the sub-table where the new key landed. The
existing sub-tables' fields are stable enough that we do not expect
this to bite in M4.

### 2.5 Why the split with `crates/glossary`

`crates/glossary` uses pure `toml` + sorted serialization
([`glossary/src/schema.rs:225-255`](../crates/glossary/src/schema.rs)).
That's the right choice for the glossary because:

1. The glossary is **machine-edited via the UI's glossary editor**
   (`ui/src-tauri/src/lib.rs:464-474`). The editor sends a payload, the
   Rust side serializes deterministically, and writes. There is no
   user-typed source structure to preserve.
2. Deterministic alphabetical sorting is a *feature* for the glossary:
   diffs stay clean across edits made by different users.
3. The glossary's TOML is shallow (`[meta]`, `[[term]]`,
   `[locale.<id>]`) and the field set is small.

The manifest is the opposite case:

1. Users **hand-edit** `i18n-harness.toml` (it sits next to `Cargo.toml`
   in shape and role). Stripping comments on save is the kind of
   small annoyance that builds resentment toward the tool.
2. The manifest's natural order is *user intent*, not alphabetical:
   the locale you care about most goes at the top.
3. New tables get added: `[prompts]`, `[paths]`, an eventual
   `[evaluation]`. Preserving the surrounding blank lines and
   comments around them matters.

So: pure `toml` + sorted output for glossary; `toml_edit` + hybrid for
manifest. Each crate's choice fits its caller pattern.

## 3. Discovery heuristic

`Project::discover(root)` runs when there is no `i18n-harness.toml` at
`root`. It walks the tree (depth-limited; see below), classifies every
candidate file, and returns a `DraftManifest` for user confirmation.

The output is **never silently persisted**. The CLI (`harness init`)
shows the draft and prompts; the UI's "Create from this folder" path
renders the draft in the home screen for confirmation before calling
`Project::create_from_draft`. This is the load-bearing constraint:
discovery is a *suggestion*, not a *commitment*.

### 3.1 Walk parameters

- Recurse from `root` skipping: `.git`, `node_modules`, `target`,
  `dist`, `build`, `__pycache__`, `.i18n-harness`, any directory whose
  name starts with `.` except `.config`. (Hidden directories almost
  never contain catalogs; exempting `.config` covers the one common
  case.)
- Max depth: 8. Catalogs typically sit at `translations/`,
  `locale/`, `i18n/`, `src/locales/` etc. — depth 8 catches every
  layout we have seen without runaway recursion on a misclicked
  `/home`.
- File-size cap for sniffing: 64 KiB read into memory. A 10 MB JSON is
  probably not a catalog; we sniff only the prefix. If a real catalog
  exceeds this, the user adds it explicitly via `add_catalog` (which
  does full validation against the actual file).

### 3.2 Format classification

For each candidate file:

1. **Extension prefilter.**
   - `.ts` → tentatively `QtTs`. (Note: `.ts` collides with TypeScript;
     see disambiguation below.)
   - `.po` → tentatively `GettextPo`.
   - `.json` → tentatively `IcuJson` (least confident — JSON files are
     everywhere).
   - Other extensions → not a candidate.

2. **Content sniff (within 64 KiB).** This is the source of truth;
   extension is only the gate.

   - **Qt `.ts`:** Look for `<TS` (with optional whitespace) within the
     first 1 KiB after skipping any XML declaration / BOM. Captures the
     `language="..."` attribute via regex
     `<TS\b[^>]*\blanguage="([^"]+)"`. If `<TS` is absent but the file
     starts with `<?xml` and we see TypeScript-style syntax
     (`import`, `export`, top-level `const`/`let`/`function`),
     reclassify as not-a-catalog. If `<TS` absent and no JS-ish
     content, return `FormatGuess::Unknown` with confidence `Low`.
     - **Disambiguation:** the simultaneous existence of `.ts` for both
       Qt Linguist files and TypeScript source is the load-bearing
       gotcha. The sniff treats it as a hard XOR: a file is either
       Qt-XML (starts with `<?xml` or contains `<TS`) or TypeScript
       (contains JS keywords in non-string context) — never both.

   - **PO:** Look for the gettext header line pattern `msgid ""` near
     the top followed by `msgstr ""` and then `"Content-Type:`. The
     `Language:` header line `"Language: <id>\n"` (note the trailing
     `\n` is part of the gettext string value) yields the locale
     with confidence `High`. Files missing the header but containing
     `msgid "..."\nmsgstr "..."` pairs match with confidence `Medium`
     and locale `None` — the user has to fill it.

   - **ICU-JSON:** Parse the JSON prefix with `serde_json` (lax —
     accept top-level either object or array). Reject if:
     - It is `package.json` (top-level keys `"name"` + `"version"`).
     - It is `tsconfig.json` (`"compilerOptions"`).
     - It contains a top-level `"$schema"` whose value is not an
       i18n-known schema URL (heuristic: contains `i18n` or
       `messageformat`).

     Accept if it looks like a flat `{ key: string }` map or a
     `{ key: { defaultMessage: string, ... } }` (Lingui shape) or
     `{ key: { string: string } }` (i18next shape). Heuristic
     confidence: `Medium` (we cannot prove a JSON file is a catalog
     without knowing the consuming library).

3. **Output a `DraftCatalog`** with the format guess, locale guess
   (see §3.3), confidence, the `reason` string the sniffer recorded,
   and any `alternatives` it found (e.g., a `.json` that could be
   either ICU-JSON or Unknown).

### 3.3 Locale inference

The strategy is **adapter-derived first, filename fallback**, in this
order:

1. **Adapter-derived (preferred):**
   - Qt: `<TS language="...">` attribute (confidence: `High`).
   - PO: `"Language: <id>\n"` header line (confidence: `High`).
   - ICU-JSON: usually none. Try a `__locale__` top-level key (some
     conventions use it); confidence `Medium` if present.

2. **Filename fallback:** apply the regex
   `(?:[_\-.])([a-z]{2,3}(?:[_-][A-Z][a-zA-Z]{1,3})?)\.(?:ts|po|json)$`
   to the basename. Examples it matches:
   - `app_de.ts` → `de`
   - `app-de_DE.ts` → `de_DE`
   - `messages.zh_Hans.json` → `zh_Hans`
   - `de.po` → `de`

   Normalize hyphens to underscores (`de-DE` → `de_DE`) to match the
   workspace's underscored convention
   ([`locales/src/lib.rs:113`](../crates/locales/src/lib.rs)). If the
   regex matches and the inferred id resolves via `Locale::by_id`,
   use it with confidence `Medium`. If it matches but does not
   resolve, surface it as `confidence: Low` and let the user
   confirm.

3. **No inference:** `locale: None`, confidence `Low`. The draft entry
   shows up in the UI with a "pick a locale" dropdown.

### 3.4 Locale block synthesis

For every distinct locale id observed across all catalogs:

- If the id resolves through `Locale::by_id`, emit a `LocaleConfig`
  with empty fields (no overrides — workspace defaults apply).
- If the id does *not* resolve, still emit the `LocaleConfig` so the
  user sees the locale in the manifest preview and can either fix the
  id (typo) or add the locale to `crates/locales`.

### 3.5 Glossary inference

If `<root>/glossary.toml` exists, set
`draft.glossary = Some(GlossaryConfig { path: "glossary.toml".into() })`.
We do not search for glossaries under arbitrary names — the convention
is `glossary.toml` at the root, period.

### 3.6 Backend inference

`backend: None` always. We do not try to guess the user's backend; the
home screen prompts for it (with "ollama at localhost:11434" as the
suggested default the user can accept with one click).

### 3.7 Ambiguity surfacing

Every `DraftCatalog` carries a `confidence` and a `reason`. The UI
sorts by confidence (High → Medium → Low) and only auto-checks the
High ones; Medium and Low require explicit confirmation. The `reason`
string is shown verbatim so the user can see *why* the heuristic
guessed what it did, and the `alternatives` vec gives them one-click
re-classification.

This is the contract: the discovery heuristic is **transparent and
recoverable** — every guess shows its work, and every guess can be
overridden before commit. We never silently classify a `dist/messages-de.json`
that turned out to be a build artifact as a real catalog.

## 4. Locale config layering

Three layers stack, deepest to surface:

1. **Workspace immutable** (from `crates/locales`):
   - `cldr_plural` (and thus `plural_arity`) — **never overridable.**
     A locale's CLDR arity is a fact about the language, not a policy.
   - `script` — **never overridable.** A script choice is intrinsic to
     the locale id; `de_DE` is Latin, period. Project-level override
     would silently change gate behavior in confusing ways.

2. **Project manifest** (`[locales.<id>]` in `i18n-harness.toml`):
   - `register` (override workspace default)
   - `variant` (override workspace default)
   - `length_warn_ratio` (override workspace default)

3. **Glossary** (`[locale.<id>]` in `glossary.toml`, see
   [`glossary/src/lib.rs:88-99`](../crates/glossary/src/lib.rs)):
   - `register` (overrides manifest)
   - `variant` (overrides manifest)
   - `length_warn_ratio` — **does not exist on the glossary side**, so
     the manifest's choice is final for that field.

The merge order is **glossary > manifest > workspace**: a glossary's
explicit `register` wins because it represents the most localized
choice (the project's translator's preference for that locale). The
manifest is the team's default; the workspace's value is the
"sensible fallback" for the locale-as-a-language.

### 4.1 Unknown locale id in the manifest

The manifest may declare `[locales.fr_FR]` before `fr_FR` is added to
`crates/locales`. Behavior:

- `Project::open` succeeds, with a `ProjectWarning::UnknownLocale {
  locale: "fr_FR" }` in the warnings vec.
- `Project::locale("fr_FR")` returns `None` (the resolved view
  requires a workspace base to derive `plural_arity`/`script` from —
  there is no honest default).
- Any catalog declaring `locale = "fr_FR"` in `[[catalogs]]` will have
  `CatalogStatus::Ok` (the file is valid) but
  `Project::open_catalog(path)` (M4.2 layer) returns an error if a
  caller actually tries to translate into a locale without a workspace
  record.

This matches the glossary's existing posture
([`glossary/src/error.rs:101-114`](../crates/glossary/src/error.rs)):
warn loudly, do not lose data, let the user fix the typo or register
the locale.

### 4.2 What `Project::locale` returns

`Some(ResolvedLocale)` only when the workspace `Locale::by_id`
resolves. The merged view threads the override layering above; see the
type's accessors in §1.6.

## 5. Error model

One `ProjectError` enum. Rationale: every consumer (CLI, Tauri layer)
calls multiple project methods in sequence and benefits from a single
error type to pattern-match against. This matches the workspace
precedent — `GlossaryError` in
[`glossary/src/error.rs:13`](../crates/glossary/src/error.rs) and
`CoreError` / `IntermediateError` in
[`core/src/error.rs:11`](../crates/core/src/error.rs) are
single-enum-per-crate. Uses `thiserror` per the workspace dep at
[`Cargo.toml:39`](../Cargo.toml).

```rust
#[derive(Debug, thiserror::Error)]
pub enum ProjectError {
    // ── Manifest ───────────────────────────────────────────────────
    /// No `i18n-harness.toml` at the given root. Caller falls back to
    /// `Project::discover`.
    #[error("no `i18n-harness.toml` at {}", path.display())]
    ManifestMissing { path: PathBuf },

    /// Manifest TOML is malformed.
    #[error("parse {}: {source}", path.display())]
    ManifestParse { path: PathBuf, source: toml::de::Error },

    /// Manifest declares a schema version newer than this binary supports.
    /// Caller: upgrade the harness.
    #[error("manifest schema {found} > supported {supported}")]
    UnsupportedSchemaVersion { found: u32, supported: u32 },

    /// Manifest is missing `[project] schema` or other required fields.
    /// `field` names the offending key in dotted form.
    #[error("manifest missing required field `{field}`")]
    MissingRequiredField { field: String },

    // ── Catalog ────────────────────────────────────────────────────
    /// A `[[catalogs]]` entry points at a non-existent file.
    /// Caller: surface to user; remove or fix the entry. Encountered
    /// in `Project::open` strict mode; `Project::discover` does not
    /// produce this (it operates on what it finds).
    #[error("catalog not found: {}", path.display())]
    CatalogNotFound { path: PathBuf },

    /// The file does not match its declared format. Caller: surface
    /// to user; offer to re-declare or remove.
    #[error("catalog {} declared {declared:?} but content looks like {sniffed:?}", path.display())]
    CatalogFormatMismatch {
        path: PathBuf,
        declared: CatalogFormat,
        sniffed: FormatGuess,
    },

    /// Two `[[catalogs]]` entries share the same path.
    #[error("duplicate catalog path: {}", path.display())]
    DuplicateCatalogPath { path: PathBuf },

    // ── Glossary ───────────────────────────────────────────────────
    /// Glossary loader failure. Transparent — the inner
    /// `GlossaryError` carries its own context.
    #[error(transparent)]
    Glossary(#[from] i18n_harness_glossary::GlossaryError),

    // ── Corrections / curated ─────────────────────────────────────
    /// JSONL line in `corrections.jsonl` cannot be parsed. Caller:
    /// surface and skip the line; the store is line-recoverable.
    #[error("malformed correction line {line_no} in {}: {source}", path.display())]
    CorrectionParse { path: PathBuf, line_no: usize, source: serde_json::Error },

    /// The id passed to `promote_to_curated` is not in
    /// `corrections.jsonl`. Caller: refresh and retry.
    #[error("correction id `{id}` not found")]
    CorrectionNotFound { id: CorrectionId },

    /// Curated set TOML is malformed.
    #[error("parse curated.toml: {source}")]
    CuratedParse { source: toml::de::Error },

    // ── I/O ───────────────────────────────────────────────────────
    /// Generic filesystem failure. `path` names what we were trying
    /// to touch; `source` is the OS error.
    #[error("io {}: {source}", path.display())]
    Io { path: PathBuf, source: std::io::Error },

    // ── Validation ────────────────────────────────────────────────
    /// `[backend.default] kind` is one we recognize but not supported
    /// in the current build (e.g. `openai-compatible` with the feature
    /// off). Distinguish from `BackendKind` parse failure so the UI
    /// can offer to rebuild or switch backend.
    #[error("backend `{kind}` not enabled in this build")]
    BackendNotEnabled { kind: String },
}
```

Warnings are non-fatal and mirror the glossary pattern:

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ProjectWarning {

    /// workspace's `Locale` table.
    UnknownLocale { locale: String },
    /// A `[[catalogs]]` entry's locale was inferred but does not
    /// resolve through `Locale::by_id`.
    UnknownCatalogLocale { path: PathBuf, locale: String },
    /// A glossary warning, threaded through.
    Glossary(i18n_harness_glossary::GlossaryWarning),

```

### 5.1 Why one enum, not per-operation

A per-operation enum (`ManifestError`, `CorrectionError`, `IoError`,
…) would let each method's signature show exactly what can fail. Two
reasons against:

1. The Tauri command layer wraps every Rust error as a string anyway
   ([`ui/src-tauri/src/lib.rs:263`](../ui/src-tauri/src/lib.rs)),
   so the discrimination is lost at the IPC boundary.
2. The CLI's existing pattern is to bubble through `anyhow::Result`
   ([`cli/src/main.rs:138`](../crates/cli/src/main.rs)) — multiple
   error enums just multiply the `Context` boilerplate without
   helping the user.

The single enum with `#[error(transparent)]` for nested errors keeps
the type ergonomic. The variant names are precise enough that the UI
can branch on them when it wants to (e.g., `CatalogNotFound` opens a
"locate file" dialog vs `CatalogFormatMismatch` opens a "re-classify"
panel).

## 6. Translation-memory data model

Two files:

```
.i18n-harness/
  corrections.jsonl    # append-only, every accepted edit
  curated.toml         # comment-preserving, references corrections by id
```

### 6.1 `corrections.jsonl` shape and keying

One JSON object per line; schema in §1.8 (`Correction`).

**Keying:** `CorrectionId` is content-addressed —
`SHA-256(catalog_manifest_path ‖ unit_id ‖ source ‖ mt_proposal ‖
human_target ‖ ts_micros)[..12]`. Provenance fields are deliberately
**not** part of the hash: two corrections that differ only in which
prompt version produced their proposal are *the same edit from the
human's perspective* and should hash the same. Including `ts_micros`
makes the id unique when the same human re-edits the same unit twice
in a row (a real workflow — they accept, look at it again, re-edit);
excluding it would collapse those into one row, losing the trail.

The hex is truncated to 12 chars (48 bits). For a single project's
correction set — bounded by translator throughput, optimistically
10k/year — collision probability is negligible (birthday bound:
~2^24 records before 1% collision risk).

**Query model:** `list_corrections(filter)` linear-scans the file.
Justification: a hot translator session produces hundreds of
corrections, not millions; a 10k-line JSONL is a few hundred KiB and
scans in milliseconds. We do not build a side index because:

- An index file is one more thing to keep in sync with the JSONL.
- The append-only invariant is *the* feature — losing it (to compact
  the index) would create a corruption risk for one-millisecond gains.
- The Quality tab (M4.9) opens the corrections file at most once per
  session and caches in memory; no per-keystroke re-scan.

If the file grows past a useful bound, the answer is rotation
(`corrections.jsonl.1`, `.2`, …) handled by a future maintenance
command — not a query-side index.

### 6.2 `curated.toml` shape

```toml
schema = 1

[[example]]
id = "corr_a1b2c3d4e5f6"
note = "We always say 'Öffnen', not 'Eröffnen', for the file menu action."

[[example]]
id = "corr_f6e5d4c3b2a1"
note = ""
```

Just a list of id references with optional notes. The actual
`(source, mt_proposal, human_target, locale, catalog, ts)` lives in
`corrections.jsonl` — we look it up by id on read.

### 6.3 Why a separate `curated.toml` (not an in-line flag in JSONL)

Both designs work; I picked the separate file. Reasons:

1. **JSONL is append-only.** Adding an `is_curated: true` field to a
   correction would mean either: (a) rewriting the whole file when
   the user un-curates (violates append-only), or (b) appending a
   "curate" event that has to be folded against the original line at
   read time (more complex than a separate file).
2. **Curated set is small.** A project might have 10k corrections but
   50 curated examples. Keeping the small set in human-editable TOML
   with notes is friendlier than grepping JSONL.
3. **Notes belong with curation, not with raw correction.** The note
   is a *teaching note* the user writes when promoting; the raw
   correction is just a recorded edit. Conflating them in one record
   pushes the JSONL schema in a direction that does not fit M4.10's
   tuning bundle (which exports the curated notes alongside the
   examples).
4. **Round-trip preservation matters for `curated.toml`.** Users
   hand-edit notes; using `toml_edit` for it (same hybrid as the
   manifest) preserves their formatting. Adding the same machinery
   inside a JSONL line is not practical.

The trade-off: a curated id whose underlying correction got deleted
(file rotation, manual edit) becomes a dangling reference. We surface
that as `CuratedExample.correction == None` rather than panic — the
UI shows the id with a "missing source" warning and lets the user
delete it.

### 6.4 Write atomicity

- `corrections.jsonl`: single `append` per record via `ProjectFs`.
  Lines are `< 4 KiB` (POSIX `PIPE_BUF`), so a crash mid-append either
  has the line or not. Same model as
  [`gate/src/metrics.rs:11`](../crates/gate/src/metrics.rs).
- `curated.toml`: `write_atomic` (temp-file + fsync + rename) on every
  `promote_to_curated` / undo-curate. The file is small (~hundreds of
  bytes per example); atomic rewrite is cheap and bulletproof.

## 7. State path resolution

**The rule:** all state files live under `<root>/.i18n-harness/`
by default. The manifest's optional `[paths] state_dir = "..."` block
overrides this to any absolute or relative path. Relative paths
resolve against the manifest's directory, not CWD.

```
my-app/
  i18n-harness.toml
  .i18n-harness/
    metrics.jsonl
    corrections.jsonl
    curated.toml
    state/
      batches.jsonl
    tuning/
      2026-05-24T12-00-00/
        examples.jsonl
        prompt.txt
        score.json
        locales.toml
        README.md
```

The `ProjectPaths` type in §1.7 is the **single resolver**. Every
crate that needs a state path goes through `Project::paths()` — the
gate's `FileSink` in
[`gate/src/metrics.rs:107`](../crates/gate/src/metrics.rs) accepts an
`impl Into<PathBuf>`, so the CLI/Tauri layer passes
`project.paths().metrics().to_path_buf()`. The gate itself stays
ignorant of any "project" notion; the project crate is the bridge.

### 7.1 Why under-root by default, configurable via manifest

Three configurations were considered:

| Option | Pro | Con |
|---|---|---|
| **Always `<root>/.i18n-harness/`** | One rule; no config to learn. | Forces big repos to have a write-set inside the source tree (some CI policies disallow this). |
| **Always system-wide cache (`$XDG_CACHE_HOME/i18n-harness/<hash-of-root>/`)** | Source tree stays clean. | Two clones of the same project lose state on each other; backups don't capture state. |
| **`<root>/.i18n-harness/` by default, manifest override** | Default works for 95% (translator-focused, local checkout); escape hatch for the 5%. | Slightly more spec to write. |

Picked the third. The default keeps state colocated with the project
(so a `cp -r` move includes the corrections and metrics); the override
lets the rare team that wants a per-user cache point at one. The
`PathsConfig` field is the minimum surface needed to enable this
without baking in environment-variable handling (we do not want
`$I18N_HARNESS_STATE_DIR` magic; explicit > implicit).

### 7.2 Portability of the manifest

If a team commits the manifest and the state dir is the in-tree
default, moving the project to another machine just works. If the team
sets `state_dir = "/home/team/i18n-state"` and commits the manifest,
that path is per-machine — but that is the explicit choice the user
made, and we document the gotcha. We do not try to be cleverer than
the user here.

## 8. Workspace integration

### 8.1 Dependencies the new crate takes

```toml
# crates/project/Cargo.toml
[dependencies]
i18n-harness-core.workspace = true
i18n-harness-locales.workspace = true
i18n-harness-glossary.workspace = true
serde.workspace = true
serde_json.workspace = true
toml.workspace = true
toml_edit = "0.23"          # NEW workspace dep
thiserror.workspace = true
sha2.workspace = true       # already in workspace, used for CorrectionId
```

The crate **does not** depend on `adapter-qt`, `catalog`, `backend`,
or `gate`. The reason: those crates are *operations* the project
crate's caller composes — pulling them in as deps would make
`Project` a god object and would couple the project's compile time to
every adapter and backend in the workspace.

The wiring lives at the consumer:

- The CLI imports both `i18n-harness-project` and `adapter-qt` and
  routes `project.catalog(path)` through `adapter_qt::extract`.
- The Tauri layer does the same.
- A future log adapter implements no new project-crate surface;
  callers thread it the same way.

### 8.2 What needs to change in other crates

| Crate | Change | Reason |
|---|---|---|
| `catalog` (new in M4) | Define `CatalogFormat` discriminator + a `sniff(bytes: &[u8]) -> FormatGuess` function. | The project crate's discovery needs format sniffing without depending on the format-specific readers. |
| `adapter-qt` | Export a small `sniff(bytes: &[u8]) -> bool` helper for Qt `.ts`. | The project crate calls it via the `catalog` aggregator (which re-exports it). Keeps the `<TS` detection logic colocated with the parser that knows about Qt. |
| `core` | No changes. | `Unit`, `UnitId`, `Flag` are already what we need. |
| `locales` | No changes. | The merged view is computed inside the project crate; `Locale` stays as `&'static`. |
| `glossary` | No changes. | `Project` consumes `Glossary` through its existing public API. |
| `gate` | No changes. | The project crate hands resolved paths and `&Locale` to the gate's existing entry points. |
| `backend` | No changes. | Same as gate — the project crate hands `&Glossary` / locale id / model name; the backend trait surface is untouched. |
| `cli` | New `init` and `open` subcommands wrapping `Project::discover` / `Project::open`. | Existing `translate` / `gate` / `round-trip` subcommands stay; M4.2 adds project-aware variants. |
| `ui/src-tauri` | M4.2 work — replaces session-state with a `Project`. | Out of scope for M4.1. |

### 8.3 Workspace `Cargo.toml` additions

In `[workspace.members]`: `"crates/project"`.

In `[workspace.dependencies]`:
```toml
toml_edit = "0.23"
i18n-harness-project = { path = "crates/project", version = "0.1.0" }
```

## 9. Public-surface review

This section flags items that could leak from the "implementation
internal" surface into the "stable API" surface. Marking them now
prevents the published 0.x surface from carrying scaffolding.

### 9.1 Keep `pub`

- All §1.1–§1.8 types as written. Each is on the path between the
  caller (CLI / Tauri / a future agent driver) and the project's state.

### 9.2 Demote to `pub(crate)`

- `ParseState`, `DiscoveryWalker`, any helper type that exists only to
  share state between parser/walker phases.
- `BatchKey` synthesis helpers (the project crate generates batch keys
  via `core::BatchKey::new(&hash, idx)` but does not expose a
  project-specific wrapper).
- `toml_edit` document handle on `Project` — exposed only through the
  mutation methods, not as `Project::doc_mut()`. Leaking `&mut
  DocumentMut` would let callers bypass the consistency invariant (doc
  is the source of truth, manifest is derived from it after every
  edit).

### 9.3 Sealed traits

- `ProjectFs` is the abstraction for testing. We **do** want external
  impls (e.g., a future S3-backed FS for cloud projects), so do not
  seal it. Document the contract clearly (atomicity guarantees, path
  semantics) and accept the breakage cost when the trait evolves.

- `CorrectionStore` is a concrete struct, not a trait. We do not
  imagine third-party correction stores; if that need arises, we can
  introduce a trait then. YAGNI for v1.

### 9.4 Items that look like debug scaffolding

None planned. Discovery's `reason: String` field is *intentionally*
human-readable and exposed, not a debug aid — it is shown in the UI.
Same for the `ProjectWarning::UnknownLocale` warning: it surfaces to
the user, not just to a log.

### 9.5 Don't expose

- The internal SHA-256 hashing function for `CorrectionId` — callers
  construct corrections via `NewCorrection` + `record_correction`,
  which generates the id internally. Exposing a `correction_id_for(...)`
  helper would invite callers to forge ids.
- The `toml_edit::DocumentMut` shape under `Project`.
- The raw `MetricEvent` type — `gate` already exposes its own; we do
  not duplicate.

## 10. Out of scope (explicit non-goals)

The following are intentionally NOT in this design and should not
accrete onto it during implementation. Each has its own milestone or
is a clear "not now" call.

| Non-goal | Where it goes |
|---|---|
| **Multi-project workspaces** (one window, many projects). | M5+. Today one `Project` per window. |
| **Project templates** (`harness new --template react`). | M5+. Starting from a directory + discovery is enough for translators today. |
| **Cloud / remote project sync.** | Out of charter (local-first invariant in `CLAUDE.md`). |
| **Watchers / hot-reload on file changes.** | M4.2 may add a one-shot "reload manifest" command. Filesystem watching is a separate UX problem. |
| **Encrypted secrets in the manifest** (API keys, etc.). | The `manual` and `ollama` backends do not need keys. When `openai-compatible` lands (M5), keys live in env vars or per-user `~/.config/i18n-harness/credentials.toml`, not in the project manifest. The manifest stays git-committable. |
| **Schema migration v1 → v2.** | Not needed yet; the loader rejects future versions cleanly. The migration plan lands with v2. |
| **A `Locale` registration API in the project crate.** | The set of locales is workspace-wide. A future request "let projects define their own locales" is a deliberate architectural change, not a minor addition. |
| **Temperature / sampling settings per correction.** | `CorrectionProvenance` covers backend / model / model_version / prompt_template_version / glossary_version — the load-bearing fields for prompt-vs-prompt comparison. Temperature is a knob that can be derived from `(backend, model_version)` for deterministic backends and is rarely material for translation work. We add it in v2 if the M4.10 tuning loop's analysis surfaces a real need. |
| **A `pub` API to compose a `Project` from non-disk parts.** | Tests use `InMemoryFs`; that is the supported test path. We do not introduce a `Project::from_parts(manifest, glossary, paths)` constructor — it would let callers construct invalid states. |

## 11. Verification surface

The crate ships these test categories:

1. **Manifest round-trip property test** (proptest). Given a synthetic
   manifest with comments, blank lines, and mixed key orderings,
   parsing → mutating one field → saving → re-parsing yields a
   manifest equal in *both* the typed view and the byte buffer (modulo
   the one field that changed).
2. **Discovery snapshot tests** (insta). For each fixture tree under
   `crates/project/tests/fixtures/discovery/<scenario>/`, the
   `DraftManifest` JSON snapshot is committed and compared on every
   run. Scenarios: Qt-only, PO-only, ICU-JSON-only, mixed,
   misclassified TypeScript file, ambiguous JSON, no catalogs.
3. **Locale layering unit tests.** For each (workspace, manifest,
   glossary) combination, assert `ResolvedLocale` returns the
   expected merged values.
4. **Correction store** (proptest). Sequences of `record_correction` →
   `list_corrections(filter)` produce the expected subset; ids are
   collision-free over a synthetic 1000-edit corpus.
5. **`InMemoryFs` parity** — every public method's happy path runs on
   `InMemoryFs` as well as `RealFs` (via `tempfile`), and outputs
   match. This is the contract that the FS abstraction is honest.
6. **Path resolution** — given a manifest with and without
   `[paths] state_dir`, `ProjectPaths::metrics()` resolves to the
   right absolute path.

The crate-level `cargo doc --document-private-items` builds clean.

## 12. Summary

The project crate is the **single owner** of the user's persistent
state outside the catalog itself. It owns the manifest (with
comment-preserving mutation via `toml_edit`), the resolved view of
locales (workspace + manifest + glossary merged), the path resolution
for every state file, the discovery heuristic with transparent
confidence levels, the translation-memory store (append-only JSONL
plus a hand-editable curated TOML), and a filesystem abstraction that
lets the whole thing be tested without touching disk.

It depends on `core`, `locales`, `glossary`, and `serde` machinery —
nothing more. It is consumed by `cli`, `ui/src-tauri`, and any future
driver; those callers compose `Project` with the catalog adapters,
backend, and gate they need. The trait surface (`TranslationBackend`,
`CatalogFormat`) stays exactly where it is today.

The two non-negotiables hold: nothing in this crate names a specific
language, engine, or format (data and dispatch only); and nothing in
this crate calls into a backend (deterministic Rust, full stop).
